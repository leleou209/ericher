AI 接待台。

ericher 跑在 Cloudflare Workers 上：你可以给它派任务、记东西、定提醒、盯进度，也可以开门让来客进来谈事。每个房间有自己的对话、记忆与文件，来客之间互不串门；主人可在自己的屋里查看来客房间的聊天记录。免费额度内自配自管，MIT 开源。

现在就试一句 看使用手册 下载部署包 在 GitHub 看源码

前提只有一个 Node 24（或 ≥22.12）与一个 Cloudflare 账号。
门牌只有一个：/assistant —— 没有票时它就是门禁登录页，登进去就是助手台。管理员用 ADMIN_PASSWORD，来客用 GATE_PASSWORD 或档位口令；没有默认口令。

它解决什么问题

不是客服机器人，也不是聊天壳。它是一个人的助手，顺便替这个人在门口接待。

  • 给自己：记事、查事、定提醒、派任务、催进度；它记得上下文，也能把没在界面上说的话寄到邮箱。
  • 给来客：发访客票或长期身份卡；对话、记忆、工具权限都关在各自的房间。
  • 给站点：在自己的域名下挂页面，按公开 / 持票 / 档位 / 管理员四档放内容。
  • 模型自己选：Anthropic / OpenAI Chat / OpenAI Responses 三种线格式；密钥只以 secret 变量名引用，不落库、不回显。

最短试用路径

  1. 打开 /assistant，用管理员口令登录。
  2. 新建对话，输入 /help。
  3. 让它记一条、定一个两分钟提醒。
  4. 无痕窗口用 GATE_PASSWORD 再看一次来客视角。

照做一遍

一件件说

下面每一条都对应仓库里已经实现的代码，不是路线图。工具按身份与档位组装，管理员与来客各有一套。

  1. 门禁与会话

    口令登录、无内置默认值 —— 没配就 503 而不是悄悄 500。会话令牌是 HttpOnly Cookie，只存 SHA-256 摘要。

  2. 身份卡

    长期客人一张卡，可换手机回到原房间；同一档位的不同来客彼此隔房，各按各的入口说话。

  3. 记忆库与向量检索

    分条记忆、向量索引、关键词搜索、时间/重要性检索；助手自己给每条标重视程度。

  4. 任务、提醒与盯梢

    待办清单、定时提醒、到点主动开口；盯梢可以每小时看一眼某个网页或指标，变了才说。

  5. 信箱

    自己的一枚 SMTP 通道：寄信、多收件人、发件流水、收信入库带附件清单。详见下一节。

  6. 网页矩阵

    在自己域名下摆一组页面，按层级导航、按页授权，还能整包导出成 zip 再读回来。

  7. 工具面

    联网搜索、读网页（带 SSRF 拦截与风险识别）、画图、多档折叠导出、语音合成、文件附件。

  8. 产物卡片

    对话里现生成自包含 HTML 小部件，沙箱 iframe 内渲染，回复不只是一段文字。

  9. 夜间整理

    主屋在北京时间 04:00 静默检查全站新会话与邮箱，提取洞察；没有新信息不启动。

信箱：它真的能寄信，也真的收得到

这一版新加的一块。发信走自研的一次性 SMTP 客户端（不是第三方 SDK），收信走 Cloudflare 的入站路由 —— 信箱本身（解析、存储、清单、读法）全在这个仓库里。

发信
管理员在界面上写一封，或者对助手说一句让它寄；一封寄多个收件人只占一格额度，额度按天记、并发不重复占。
加密
465 隐式 TLS 与 587 STARTTLS 都实测过。升级失败就断连，绝不在明文上发凭据；证书主机名钉死。
流水
每一封都记账，失败也记并留服务器原话 —— 只记成功的账本等于没账本。
收信
头部进 DO 的 SQLite，整封原件进 R2；按内容指纹去重，超出保留数时连原件一起裁。
附件
清单只记名字与大小，内容一概不落库；正文只取纯文本，HTML 永不作为 HTML 交给上层。
离线副本
到点要说的话如果没进你当前那一场的对话流，就攒成一份邮件寄给你 —— 默认关着，一开就生效。
安全
口令只存在 secret 变量名里；来信被当作外部材料框住交给助手，不当作指令执行；寄信与收信只给主人这一间。

一个 DO 就是一间屋

整条链路只有三层：测试只打 Worker，Worker 按身份把你的话转给那间屋。屋里的东西全在它自己身上。

kind=host

主人屋 default

只有管理员进得去。全套工具、配置、夜间整理、全局皮肤都在这里。

kind=card

持卡来客

由稳定身份派生，可换设备回到原房间。能看见自己这间屋的对话与记忆，看不见别人的。

kind=temp

一次性入口

匿名 cookie 生成。换了手机、或者清了 cookie，就找不回原房间 —— 要长期请领一张卡。

矩阵：外院展示，内院谈事，核心自留

推荐双层宅院。外院谁都能看；过一道门卫进内院；核心区只有管理员。权限在服务端判定，不靠前端藏链接。

外院 · public

介绍、作品、公开文章、联系页。无登录、无隐私数据；入口页只能有一个，且必须公开。

内院 · visitor / types

持票来客或指定档位可见；每个来客仍在自己的房间，记忆与文件不串。

核心 · admin

设置、信箱、模型、来客名册、矩阵工作台、备份。只给管理员，不从公开页挂链接。

两道墙：公开→持票走 /_ticket 验票；持票→管理员由 access=admin 判定。外站跳转统一走 /_gate，域名要先认定。

下载与部署

两条路：下载预构建包（不装构建链），或从源码构建。最后都是 npx wrangler@4 deploy。

方式 A · 下载预构建包

包内是完整的 Worker 产物、静态资源与 wrangler.jsonc，不含密钥；解压后直接部署，不需要 npm install 或 npm run build。

下载页：GitHub Releases · 当前 ericher-0.1.7-cf.zip（2,896,891 字节）· SHA-256 782edac4460882d03a16b9f1b3ce069152d4b44a261a7cc5fda938654a82b9a6

curl -L -o ericher-0.1.7-cf.zip \
  https://github.com/leleou209/ericher/releases/download/v0.1.7/ericher-0.1.7-cf.zip
sha256sum ericher-0.1.7-cf.zip
# Windows: Get-FileHash .\ericher-0.1.7-cf.zip -Algorithm SHA256

unzip ericher-0.1.7-cf.zip -d ericher-0.1.7-cf
cd ericher-0.1.7-cf

npx wrangler@4 r2 bucket create ericher-memory
npx wrangler@4 vectorize create ericher-memory-bge-m3 --dimensions 1024 --metric cosine
npx wrangler@4 secret put API_ENDPOINT
npx wrangler@4 secret put API_KEY
npx wrangler@4 secret put API_MODEL
npx wrangler@4 secret put ADMIN_PASSWORD
npx wrangler@4 secret put GATE_PASSWORD
npx wrangler@4 secret put SESSION_SECRET
npx wrangler@4 deploy

Dashboard 直接上传单个 index.js 带不上 Durable Objects / R2 / Vectorize 绑定和静态资源；完整部署必须用 npx wrangler@4 deploy。包内 DEPLOY.md 有同样步骤。

方式 B · 从源码构建

适合要改代码的人。第 4 步先 dry-run 看清目标，再真部署。

1拉取与依赖

git clone https://github.com/leleou209/ericher.git
cd ericher
npm install
npm run types

2建两个专用资源

npx wrangler r2 bucket create ericher-memory
npx wrangler vectorize create ericher-memory-bge-m3 \
  --dimensions 1024 --metric cosine

名字要与 wrangler.jsonc 对应，改了就两步都改。

3配 secret

npm run types  # 生成 worker 类型
npx wrangler secret put API_ENDPOINT
npx wrangler secret put API_KEY
npx wrangler secret put API_MODEL
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put GATE_PASSWORD
npx wrangler secret put SESSION_SECRET
# 要用信箱再加一把：
npx wrangler secret put MAIL_KEY

来客口令与管理口令不要相同；只给 GATE_PASSWORD 的话，管理员进不了自己的全套工具。

4看目标，再部署

npm run check          # 类型 + 1434 例 + 构建
npm run deploy -- --dry-run
npm run deploy

部署到你自己域名下，就配 .wrangler.local.jsonc 走 npm run deploy -- --private。

给 AI：先下载 zip 并校验 SHA-256，解压后读 DEPLOY.md，再建资源、配 secret、npx wrangler@4 deploy；不要只传 index.js。

先说清它不做什么

这类事提前讲明白，比事后发现强。

没有独立数据库服务

全在你自己的 DO 与 R2 里。管理员导出 /api/export 拿一份 JSON —— 定期备份是运维的一部分，不是可选项。

换口令不等于收房间

改 GATE_PASSWORD 只影响之后的登录，不会踢掉已在线的房间；改 SESSION_SECRET 会让所有票失效，对话与记忆原地保留。

本地开发要登录 CF

Browser Run / Vectorize / Workers AI 无法在本地 workerd 里模拟，npm run dev 仍走远程绑定。

第三方渲染有额度

read_url 读前端渲染页面走 Browser Run，免费档每天 10 浏览器分钟；没启用时自动回退「直连 + Jina」路径。

信箱要一把真钥匙

发信需要一个能用的 SMTP 账号（自建域名的 relay 或免费档服务商都行），25 端口平台封着，用 465 或 587。

它是个人的项目

使用 Vibe coding 写成，代码与版本管理经验多有残缺。质量口径是 npm run check 与全量测试，但也请你对自己那套负责。

自己部署，自己掌握。
