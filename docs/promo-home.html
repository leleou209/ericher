两种人，两种用法

  • 给自己用：记事、查事、定提醒、派任务、催进度、写周报。它记得你上次说到哪儿，也会在你没界面前把话寄到你邮箱。
  • 给别人用：开一张访客票或发一张长期身份卡，客人进来谈事；他的对话、记忆、能用的工具，都关在他自己那间屋里。
  • 不联网也能用：模型走你自己的 OpenAI / Anthropic / OpenAI-Responses 三种协议，密钥只以 secret 变量名的形式被引用，不落库、不回显。

一件件说

下面每一条都对应仓库里已经实现的代码，不是路线图。工具面一共 28 件，管理员与来客各有一套，权限按档位开关。

  1. 门禁与会话

    口令登录、无内置默认值 —— 没配就 503 而不是悄悄 500。会话令牌是 HttpOnly Cookie，只存 SHA-256 摘要。

  2. 身份卡

    长期客人一张卡，可换手机回到原房间；同一档位的不同来客彼此隔房，各按各的入口说话。

  3. 记忆库与向量检索

    分条记忆、向量索引、关键词搜索、时间/重要性检索；助手自己给每条标重视程度。

  4. 任务、提醒与盯梢

    待办清单、定时提醒、到点主动开口；盯梢可以每小时看一眼某个网页或指标，变了才说。

  5. 信箱

    自己的一枚 SMTP 通道：寄信、多收件人、发件流水、收信入库带附件清单。详见下一节。

  6. 网页矩阵

    在自己域名下摆一组页面，按层级导航、按页授权，还能整包导出成 zip 再读回来。

  7. 工具面

    联网搜索、读网页（带 SSRF 拦截与风险识别）、画图、多档折叠导出、语音合成、文件附件。

  8. 产物卡片

    对话里现生成自包含 HTML 小部件，沙箱 iframe 内渲染，回复不只是一段文字。

  9. 夜间整理

    空闲时段自动回顾对话、萃取洞察、写记忆摘要 —— 它自己会长记性。

信箱：它真的能寄信，也真的收得到

这一版新加的一块。发信走自研的一次性 SMTP 客户端（不是第三方 SDK），收信走 Cloudflare 的入站路由 —— 信箱本身（解析、存储、清单、读法）全在这个仓库里。

发信
管理员在界面上写一封，或者对助手说一句让它寄；一封寄多个收件人只占一格额度，额度按天记、并发不重复占。
加密
465 隐式 TLS 与 587 STARTTLS 都实测过。升级失败就断连，绝不在明文上发凭据；证书主机名钉死。
流水
每一封都记账，失败也记并留服务器原话 —— 只记成功的账本等于没账本。
收信
头部进 DO 的 SQLite，整封原件进 R2；按内容指纹去重，超出保留数时连原件一起裁。
附件
清单只记名字与大小，内容一概不落库；正文只取纯文本，HTML 永不作为 HTML 交给上层。
离线副本
到点要说的话如果没进你当前那一场的对话流，就攒成一份邮件寄给你 —— 默认关着，一开就生效。
安全
口令只存在 secret 变量名里；来信被当作外部材料框住交给助手，不当作指令执行；寄信与收信只给主人这一间。

一个 DO 就是一间屋

整条链路只有三层：测试只打 Worker，Worker 按身份把你的话转给那间屋。屋里的东西全在它自己身上。

kind=host

主人屋 default

只有管理员进得去。全套工具、配置、夜间整理、全局皮肤都在这里。

kind=card

持卡来客

由稳定身份派生，可换设备回到原房间。能看见自己这间屋的对话与记忆，看不见别人的。

kind=temp

一次性入口

匿名 cookie 生成。换了手机、或者清了 cookie，就找不回原房间 —— 要长期请领一张卡。

四步，装到你自己的账号下

命令照 README 抄即可。第 4 步先 dry-run 看清目标，再真部署。

1拉取与依赖

git clone https://github.com/leleou209/ericher.git
cd ericher
npm install
npm run types

2建两个专用资源

npx wrangler r2 bucket create ericher-memory
npx wrangler vectorize create ericher-memory-bge-m3 \
  --dimensions 1024 --metric cosine

名字要与 wrangler.jsonc 对应，改了就两步都改。

3配 secret

npm run types  # 生成 worker 类型
npx wrangler secret put API_ENDPOINT
npx wrangler secret put API_KEY
npx wrangler secret put API_MODEL
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put GATE_PASSWORD
npx wrangler secret put SESSION_SECRET
# 要用信箱再加一把：
npx wrangler secret put MAIL_KEY

来客口令与管理口令不要相同；只给 GATE_PASSWORD 的话，管理员进不了自己的全套工具。

4看目标，再部署

npm run check          # 类型 + 1435 例 + 构建
npm run deploy -- --dry-run
npm run deploy

部署到你自己域名下，就配 .wrangler.local.jsonc 走 npm run deploy -- --private。

先说清它不做什么

这类事提前讲明白，比事后发现强。

没有数据库后端

全在你自己的 DO 与 R2 里。管理员导出 /api/export 拿一份 JSON —— 定期备份是运维的一部分，不是可选项。

换口令不等于收房间

改 GATE_PASSWORD 只影响之后的登录，不会踢掉已在线的房间；改 SESSION_SECRET 会让所有票失效，对话与记忆原地保留。

本地开发要登录 CF

Browser Run / Vectorize / Workers AI 无法在本地 workerd 里模拟，npm run dev 仍走远程绑定。

第三方渲染有额度

read_url 读前端渲染页面走 Browser Run，免费档每天 10 浏览器分钟；没启用时自动回退「摘要 + Jinja」路径。

信箱要一把真钥匙

发信需要一个能用的 SMTP 账号（自建域名的 relay 或免费档服务商都行），25 端口平台封着，用 465 或 587。

它是个人的项目

使用 Vibe coding 写成，代码与版本管理经验多有残缺。质量口径是 npm run check 与全量测试，但也请你对自己那套负责。
