ericher 使用手册

这份手册只回答三件事：怎么把它跑起来；每个组件在什么时候初始化、数据放在哪；按自己的需求怎么改。命令和入口都按当前仓库可执行，不写“未来会有”。

适用 0.1.7 · 95 个测试文件 / 1435 例 · 零外部请求

1. 五分钟试用

先分清两个入口：/home 是介绍页（你现在看的手册也在这一组页面里），/assistant 才是登录与助手本体。没有票时，/assistant 就是门禁页；登录成功后仍是这个地址。

管理员（主人）

  1. 打开 https://你的域名/assistant，输入部署时设置的 ADMIN_PASSWORD。
  2. 点“新建对话”，输入 /help，看当前可用的工具与命令。
  3. 说一句“记一条：周五交电费”，再打开“笔记本”或“上下文记忆”，确认它已经落库。
  4. 说一句“两分钟后提醒我喝水”，等两分钟，确认主动消息到达。
  5. 点左下角身份卡，确认称呼；打开“设置”，从上到下看一遍各节，知道东西都在哪。

来客

  1. 向管理员要一个来客口令（GATE_PASSWORD）或某档来客类型的口令。
  2. 在登录页输入口令。来客只会看到自己的对话、记忆与获准的工具，看不到设置、信箱、矩阵与别人的房间。
  3. 如果拿到了长期身份卡，换设备登录同一张卡可以回到原房间；临时票换设备不保证找回。
没有默认口令没有配置任何口令时，登录页返回 503“门禁未配置”，这是故意设计，不是密码错误。管理员口令与来客口令必须不同。
试用的边界对话会真实写入 DO 的 SQLite；不要在试用时输入不希望留存的内容。管理员可以用 /api/export 导出整库备份。

2. 部署与初始化

2.1 前置

  • Node.js 24（或 ≥ 22.12），一个 Cloudflare 账号。
  • 一个可用的模型接口（Anthropic / OpenAI Chat / OpenAI Responses 三种线格式之一）。
  • 可选：SMTP 账号（发信）、Tavily key（搜索）、语音/绘图 key。没配时对应功能自动降级或关闭。

2.2 从仓库部署

git clone https://github.com/leleou209/ericher.git
cd ericher
npm install
npm run types

npx wrangler r2 bucket create ericher-memory
npx wrangler vectorize create ericher-memory-bge-m3 --dimensions 1024 --metric cosine

npx wrangler secret put API_ENDPOINT
npx wrangler secret put API_KEY
npx wrangler secret put API_MODEL
npx wrangler secret put ADMIN_PASSWORD
npx wrangler secret put GATE_PASSWORD
npx wrangler secret put SESSION_SECRET

npm run check
npm run deploy -- --dry-run
npm run deploy

已有自己的域名与 Worker 时，把现用配置另存为 .wrangler.local.jsonc（已被 git 忽略），并用 npm run deploy -- --private；公开配置只部署到示例 Worker ericher-app。

2.3 必需 secret

名字用途要点
API_ENDPOINT模型接口地址OpenAI / Anthropic 兼容端点；也可在“模型配置”面板里改用运行时配置
API_KEY模型密钥只以 secret 变量名被引用，不入库、不回显
API_MODEL模型名要与端点支持的模型一致
ADMIN_PASSWORD管理员口令人能敲出来的口令；与来客口令不同
GATE_PASSWORD通用来客口令没有它时管理员仍可用管理员口令进入自己的屋
SESSION_SECRET会话票签名独立随机值；更换会让旧票全部失效

可选：MAIL_KEY（SMTP 口令）、TAVILY_API_KEY、ZHIPU_KEY / MIMO_API_KEY / DOUBAO_TTS_KEY（语音）、SILICONFLOW_API_KEY / MINIMAX_KEY（绘画）、CF_ACCOUNT_ID + CF_API_TOKEN（额度校准）。完整清单见仓库 .dev.vars.example。

2.4 第一次请求时发生了什么

Worker
门禁与路由先启动；没有口令直接 503。静态资源由 ASSETS 绑定托管。
DO
第一次进房时唤醒 CoworkAgent；建表、补列、读默认配置都在这一层完成。
SQLite
对话、消息、记忆、来客类型、模型/读音配置、行为留痕都在各自房间里。
R2
ericher-memory 存文件、图片、邮件原件、矩阵正文与配置。
Vectorize
ericher-memory-bge-m3（1024 维，cosine）存记忆向量；本地 workerd 不支持它。
矩阵
第一次访问矩阵路径时读 R2 的 matrix/config.json；没有就落默认配置。
不要改类名DO 存储按类标识派生。把 CoworkAgent 改名会导致既有记忆读不到；迁移标签同理。

3. 组件地图

先看一张总表，再按需往下翻。每个组件都按“入口 / 初始化 / 怎么用 / 怎么改 / 边界”写。

3.1 门禁、会话与身份

初始化：Worker 启动时只读 secret，不建默认口令。登录成功才签发 HMAC 签名的 HttpOnly Cookie；票里带角色、来客类型与卡片信息。管理员连 default 屋；来客的 DO 名由签名密钥派生，Worker 入口再核对一遍角色，防止来客改进主人的屋。

  • 角色：管理员、持票来客、临时来客、公开访客（矩阵用）。
  • 来客类型：“设置 → 来客设置 → 来客类型”维护名称、口令、权限开关与接待说明。口令只存 SHA-256 摘要；同档不同来客仍物理隔离。
  • 身份卡：长期来客可跨设备回到原房间；临时票不提供跨设备找回。
  • 换口令：只影响之后的登录，不会撤销已签发的票；换 SESSION_SECRET 才会让旧票全部失效。

3.2 对话、模型与上下文

初始化：每个房间的 DO 第一次醒来时建会话表与默认状态；模型配置优先读面板里的运行时条目，没有才回落到 API_ENDPOINT/API_KEY/API_MODEL 三件套。一次对话的历史、工具调用与 token 计数都在 DO 里。

  • 模型配置：“设置 → 模型配置 → 模型配置”。支持 anthropic、openai-chat、openai-responses；普通与深度思考可指派不同配置。
  • 密钥：面板只存 secret 变量名，运行时再从环境取；不要把 key 粘进页面或矩阵 HTML。
  • 上下文：“设置 → 对话 → 回复风格 / 上下文记忆”控制语气与记忆注入；会话记录可导出/清理。
  • 工作守则：“设置 → 工作守则”里的人格里写“怎么做事”，不是营销文案；改完用一轮真实对话验收。

3.3 记忆、回想、笔记与人物

初始化：DO SQLite 建记忆表；写入时同步生成向量进 Vectorize。会话停满 30 分钟会自动整理存档（回想）；夜间空闲时段也会做回顾。记忆权限关闭的来客一次数据回调都不该收到。

  • 上下文记忆：分条记忆、重要度、类型、书架、可见性（private / public）。“公开账本”是管理员明确点头后给来客看的那一份。
  • 人物记忆：一个人的称呼、关系与相关记录；同名同姓时用称呼区分。
  • 笔记：侧栏“笔记本”是管理员的长期本子；来客能否使用由档位权益决定。
  • 回想：按时间回看会话；会话记录在“设置 → 储存内容 → 会话记录”。
  • 个性化：“设置 → 工作守则 → 回想守则”控制怎么整理；隐私边界用记忆的可见性，而不是靠提示词自觉。

3.4 工具与技能

初始化：工具按当前身份与档位组装进上下文；工具自己只拿到必要的上下文与密钥名。搜索、读网页、绘画、语音、天气、artifact、文件附件等都可能因没配 key 而降级或关闭。

搜索

Tavily；没有 key 时退到免费渠道并标注来源。

读网页

Tavily → 直连 → Browser Run → Jina 四级兜底；带 SSRF 防护与风控识别。

绘画

按可用 key 逐级降档；没配就明确说画不了，不假装成功。

语音

MiMo / 豆包 / 智谱多协议；在“读音配置”里选。

artifact

对话里生成自包含 HTML 小部件，沙箱 iframe 渲染。

文件

小图内联直读；大图/冷门格式转述；附件进 R2，按房间前缀隔离。

权限：“设置 → 来客设置 → 来客权限管理”按档位开关工具；管理员默认全开。工具的提示词在“设置 → 工作守则 → 工具守则”里改，不要在前端硬编码另一套。

3.5 任务、提醒与盯梢

初始化：提醒与任务落在 DO SQLite；DO 被唤醒时恢复调度。到点后优先在当前对话流里说话；如果没进当前这一场，可攒成一封邮件寄出（默认关，需在邮件配置里打开 sayMail）。

  • 自然语言创建：“明天九点提醒我……”；也可在“任务清单/提醒”里手动维护。
  • 盯梢按小时级频率检查网页或指标，变化才说；注意目标站的额度与反爬限制。
  • 夜间默认不主动开工；需要时在配置里改时段。

3.6 信箱

初始化：邮件配置只存在主人屋 default 的 SQLite；场屋读到的是空表，所以发信、收信、配置类调用都会转交主屋。口令只存 secret 变量名（如 MAIL_KEY），发信那一刻才从环境取。

发信
“设置 → 寄信 → 邮件”填 SMTP 主机、端口、加密方式、账号、发件地址、默认收件地址表、每日额度；保存后用“测试发送”。465 隐式 TLS 与 587 STARTTLS 都支持；升级失败即断连，不在明文上发凭据。
发件箱
侧栏“信箱 → 寄出”。每一封都记流水，失败也记并留服务器原话；超出保留数剪到最新 200 条。
收信
Cloudflare Email Routing 把入站交给 Worker 的 email()：头部进 SQLite，整封原件进 R2 mail/in/<日>/<id>.eml，按 SHA-256 去重。收件箱最多 500 条，超限连原件一起裁。
收信开关
邮件配置里的 inboxEnabled 默认关；打开后才把来信落库。测试可用 npm run feed:mail -- --base http://127.0.0.1:8787 --pw <管理员口令> 喂一封本地样例。
真收信三步
在 Cloudflare 域名下开 Email Routing、把 MX 交给 Cloudflare、把投递目标设为这个 Worker。三步缺一不可；代码侧只剩平台投递这一跳无法在本地验证。
来信不是指令公网任何人都能往信箱里写。界面与工具都会把来信框成“外部材料”，不当作主人交代的任务或系统指令执行；HTML 永不作为 HTML 交给上层。

3.7 外观、主题与 PWA

初始化：主题配置由管理员保存，登录页也能读到全局皮肤；未登录时走公开主题接口。四套内置主题：白纸黑字、晨曦、夜墨、跟随系统。外观可整套打包成主题包（zip）导入导出，并带可视化编辑器。

  • “设置 → 外观 → 主题 / 壁纸与配色 / 形象与弹页 / 动效与消息”分别管色板、背景、头像与进站弹页、动效。
  • PWA：浏览器“安装到主屏”即可；需要 HTTPS。
  • 矩阵页面另有自己的外观注入，“设置 → 网页矩阵”里改的是矩阵那一套，不要和主应用主题混为一谈。

3.8 额度、备份与更新

  • 额度：设置里的额度面板显示自计量；配置只读的 CF_API_TOKEN 与 CF_ACCOUNT_ID 后可校准官方用量。不要把这些写进公开的 wrangler.jsonc。
  • 备份：管理员访问 /api/export 下载整库 JSON（记忆、会话、消息、配置、留痕）。数据只在你的 DO/R2 里，没有异地副本；定期拉一份是运营的一部分。
  • 更新：version.json 是发布清单；线上实例拿它比版本号决定是否提示升级。私有部署攒批推送是常态，提交号对不上不代表旧。
  • 成本：在 Cloudflare 免费额度与自备模型/SMTP 额度内可以零月费跑；Browser Run 免费档每天 10 个浏览器分钟，超出或启用付费能力时以平台账单为准。

4. 个性化：从不动代码到改代码

按改动成本从低到高选一层，不要一上来就改源码。

层能改什么在哪验收
界面配置称呼、签名、主题、壁纸、头像、动效、模型、读音、搜索、绘画、邮件“设置”各节保存后刷新仍在；换设备仍生效
行为提示人格、工具偏好、回想方式、自我认知“设置 → 工作守则”用一轮真实任务验收，不看提示词自评
权限与房间来客类型、工具权限、记忆可见性、公开账本“设置 → 来客设置 / 对话”分别用管理员、持票来客、临时来客验收
矩阵页面、路径、四档权限、导航、外站认定、页面 CSS“设置 → 网页矩阵”或 /assistant/workbench公开/持票/管理员三种身份各走一遍
源码默认提示词、工具实现、前端界面、注入样式src/agent/prompt.ts、src/tools/*、web/src/*npm run check 全绿，并在实机走一遍
先改提示词，再改代码很多“它不够像我”的问题在“工作守则”里就能解决；代码只负责能力边界，不负责语气。

5. 矩阵：双层宅院与三片权限活动域

矩阵不是“再挂几个页面”，而是一套按身份分层的站点结构。推荐把它设计成一座双层宅院：外院负责展示，谁都能进；内院要过门卫，给持票来客；核心区只有管理员能进。

5.1 三片活动域

展示域 · 外院 public

介绍页、作品、公开文章、联系方式。无登录、无隐私数据、可被搜索引擎收录。入口页只能有一个，且必须是公开页。

协作域 · 内院 visitor / types

持票来客或指定档位能看到的内容：项目进度、家庭页、共享资料。每个来客仍在自己的房间里，记忆与文件不串。

管理域 · 核心 admin

设置、信箱、模型配置、来客名册、矩阵工作台、备份导出。只给管理员；不要从公开页直接挂链接。

5.2 两道墙

  • 外墙（门卫墙）：公开访客撞上 visitor / types / admin 页面时，会得到“这一页要验票”，跳到 /_ticket?next=...。验票成功才进内院；没票的人进不去。也可以用 kind=gate 的门卫节点，让“进内院”成为一个明确的入口。
  • 内墙（管理墙）：access=admin 的页面只对管理员开放；来客即使登录也只会看到“这一页不向你开放”。权限判定在服务端，页面里藏链接不算保护。

5.3 四档身份怎么选

access谁能看适合
public所有人，包括没有票的过路人介绍页、作品、公开文章、联系页
visitor任何已登录的持票来客内院首页、共享项目、给所有来客的资料
types登录且来客类型在 types 白名单里家人、朋友、客户等不同档位的专属页
admin只有管理员核心区、配置页、内部台账

5.4 一套最小可行布局

/home                  public   入口页（entry=true）
/about                 public   介绍
/work                   public   作品 / 公开文章

/inner                  visitor  内院首页（或 kind=gate 到 /inner/home）
/inner/projects         visitor  所有来客可见
/inner/family           types    types=["family"] 才可见

/core                   admin    核心区
/core/mail              admin    信箱（或直接用 /assistant）
/core/matrix            admin    矩阵工作台
/core/backup            admin    备份说明

路径规则：最多 3 段，每段只含小写字母、数字、-、_；不能占用 api、agents、assets、index、assistant。入口页最多一个，且会被强制设为公开。

5.5 在矩阵工作台里怎么搭

  1. 打开 /assistant/workbench（或“设置 → 网页矩阵”）。先建外院页，把 /home 设为入口。
  2. 建内院页，access 选 visitor；需要按档位区分时选 types 并填来客类型 id。
  3. 要一个明确的“进内院”入口，就建 kind=gate 的门卫节点，连一条边到内院首页；门卫自己不出正文。
  4. 建核心区页，access 选 admin；不要从公开页挂链接，只从工作台或助手台进入。
  5. 用“通路”把页面连起来：按钮落在正文锚点、拖拽落点或页面末尾的兜底栏。外站跳转统一走 /_gate，域名需先在外站认定表里放行。
  6. 三种身份各验一遍：无痕窗口（公开）、来客口令（持票）、管理员口令（核心）。
  7. 改动前先导出矩阵包；装备新包前会留底，出问题用“回滚”装回上一版。

5.6 矩阵包与回滚

  • 导出：工作台“导出矩阵包”或 GET /api/matrix/pack，得到一个 zip（配置 + 页面正文；缺失正文会在回执头里如实标出）。
  • 装备：POST /api/matrix/pack（管理员，或配置了 MATRIX_PUSH_TOKEN 的自动化）会整体替换当前矩阵，并在替换前留底。
  • 回滚：POST /api/matrix/pack/rollback 装回上一份留底。
  • 页面正文上限 2MB；入口页、外站页、门卫/助手节点各有独立规则，保存时会收口。
公开页就是公开的矩阵把 HTML 原样存进 R2 并直出。不要把密码、key、内部地址、客人真名与私人资料写进 public 页面；需要保护的内容放进内院或核心区。

6. 给 AI 的执行清单

这一节给代为操作的人或 AI。每步都有可验证的结果；任一步失败就停，不要靠猜连续重试。

6.1 部署与门禁

  • Node ≥ 22.12；npm install 与 npm run types 成功。
  • R2 桶与 Vectorize 索引已创建，名字与 wrangler.jsonc 一致。
  • 六个必需 secret 已配置；ADMIN_PASSWORD != GATE_PASSWORD。
  • npm run check 全绿；npm run deploy -- --dry-run 的目标是预期 Worker。
  • 打开 /assistant，管理员口令返回 200 且角色为 admin；无口令时为 503。

6.2 对话、记忆、提醒

  • 模型配置保存后，发一句“只回复 OK”，确认不走 fallback 报错。
  • 说“记一条：验收标记 <时间>”，在“上下文记忆”里能搜到。
  • 说“两分钟后提醒我验收”，到点收到主动消息；若开了离线副本，发件箱有记录。
  • 关闭某个来客档位的记忆权限，用该档位登录，确认一次数据回调都没有。

6.3 信箱

  • 邮件配置保存成功；用“测试发送”收到测试信。
  • 发件箱出现一行；失败时也有一行并带服务器原话。
  • 打开 inboxEnabled；npm run feed:mail 喂一封，收件箱出现且重复投递被判重。
  • 真收信另验三步：Email Routing、MX、目标 Worker。

6.4 矩阵

  • 外院 /home 公开且是唯一入口；无痕窗口能打开。
  • 内院 visitor 页：无票跳 /_ticket，持票能看。
  • types 页：别的档位登录只看到“不向你开放”。
  • admin 页：来客看不到，管理员能看。
  • 外站链接只走 /_gate，未认定的域名被拦。
  • 改动前导出矩阵包；装备后检查页面数与入口数；需要时回滚。

7. 排错

现象先查处理
登录页 503“门禁未配置”ADMIN_PASSWORD / GATE_PASSWORD至少配一个；管理员与来客口令必须不同

模型 401 / 404端点、模型名、key、线格式在“模型配置”里逐项对齐；先发一句最短消息

8. 安全与边界

  • 凭据：.dev.vars、.wrangler.local.jsonc、任何真实 key 都不进公开仓库；secret 只存变量名。
  • 口令：管理员与来客口令不同；不要把口令写进矩阵公开页；怀疑泄露就轮换 SMTP/模型 key。
  • 房间：一个 DO 一间屋；配置与邮件只认主人屋。来客改进不了主人的屋，但管理员也不要把管理员票发给来客。
  • 来信：当外部材料处理，不当指令；HTML 不直出；体积、条数、附件都有上限。
  • 矩阵：公开页就是公开的；内院靠服务端 access 判定；外站跳转经 /_gate 且域名要认定。
  • 备份：/api/export 是唯一整库导出；没有异地副本，定期拉取。
  • 项目边界：这是单人/小家庭的接待台，不是给大量陌生访客做客服路由的 SaaS；免费额度适合轻量使用，超出时按自己的 Cloudflare 与服务商账单为准。
